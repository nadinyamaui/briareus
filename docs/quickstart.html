Getting started

Your first session

Four things have to exist before an agent can touch a repository: a provider to run it on, a project describing the repository, optionally a database server for the session to claim, and a session. This page does all four in order, on a small Node repository; the Projects page explains every field it skips past.

Before you start

The server is running (Installation), you can reach http://localhost:4300, and the boot log did not complain about a missing .env key.

1. Register a provider

A provider is one agent CLI, configured: which binary it runs, how it authenticates, and which models it offers. Go to Settings → Providers → ＋ New.

  1. Label and binary

    Name it whatever the picker should read (Claude is fine) and pick claude (Claude Code) as the binary. The dropdown offers claude, codex, grok and opencode; those four are the only hardcoded part of the system, and every provider entry is built on one of them.

  2. Mode

    Login uses a subscription sign-in kept in a login directory of this entry's own, so it never disturbs the CLI login you use in your terminal. Press Log in, follow the browser flow, paste the code back and press Finish. API token takes a key instead and, with a Base URL, points the binary at a compatible endpoint that is not the vendor's own.

  3. Test it

    Press Test. It runs the binary for real and reports back: an entry that cannot answer here will not answer in a session either.

  4. Save

    Leave Models and Efforts empty to take the CLI's own lists. The full field reference is on Providers.

2. Add a database server (optional)

Skip this if your project has no database. Otherwise: a session that claims a server holds it exclusively while it is open, which is what stops two parallel sessions from truncating each other's tables. Go to Settings → Database pool → ＋ New.

  • Host / Port: 127.0.0.1 and 3307, say, for a second MySQL you run beside your own.
  • Username / Password: an account that may CREATE DATABASE, because the session's database is created on demand.
  • Press Test connection, then Save.
The pool is the session cap

One session holds one server at a time, so as many sessions may be open at once as there are entries. Add one entry per session you want to run in parallel. Details, including how to run several throwaway MySQL instances cheaply, on Database pool.

3. Create the project

Go to Settings → Projects → ＋ New and fill in four fields.

Repository

owner/name, exactly as GitHub spells it. Cloned over HTTPS with this machine's own git credentials.

Setup commands

One shell command per line, run in the fresh checkout before the agent starts. The first failure aborts the session. 

npm ci
npm run build
Database

The database name the session points at, e.g. my_app. Tick Give each session a database server of its own if you added a pool entry above. Migrations and seeding belong in the setup commands; they run on every session, against the claimed server.

Run commands

What ▶ Run executes. Chained, so the last one is the server that keeps running; {port} is the session's own app port. 

npm run dev -- --port {port}

Press Save. The project appears in the composer's picker immediately.

4. Start the session

  1. Open the dashboard

    Back to /, and press New session.

  2. Set the chips

    Above the message box: the workspace mode (⌗ Worktree, a clone of its own, or ⌂ Local), the project, the branch, then the provider, model and effort. They lock once the session starts, so the first turn is where they are decided.

  3. Say what you want

    Type the task and send. The session claims a workspace slot and a database server, prepares the checkout (fetch, branch, .env, setup commands) and only then hands your message to the agent. The first run on a fresh clone is the slow one; afterwards the installs are skipped whenever the manifests have not changed.

  4. Watch it work

    Output streams live. Tool calls collapse into a run you can open; the turn's footer shows its tokens, its time and, when the CLI reports one, its cost.

  5. Run the app

    Press ▶ Run in the header. The project's run commands are executed in this session's checkout, on this session's port, against this session's database, and the page opens in a new tab.

  6. Close it

    Close releases the workspace slot and the database server; the conversation stays readable and can be reopened. 🗑 deletes the record and its log; the cost ledger keeps its numbers either way.
